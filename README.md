# Jobly — React + Python + SQLite (локальная демоверсия)

## Требования и запуск
Node.js 22 LTS и Python 3.10+.
Распакуйте проект. Откройте два терминала в его папке.

Терминал 1:
```sh
python server.py
```
На Windows можно использовать `py server.py`, на Linux/macOS — `python3 server.py`.
Python-зависимости устанавливать не нужно: используются стандартные библиотеки.

Терминал 2:
```sh
npm install
npm run dev
```
Откройте адрес, который напечатает Vite (обычно http://localhost:5173).
Не открывайте index.html двойным щелчком: нужны оба сервера.
Для проверки сборки: `npm run build`. Команда preview сама по себе не проксирует API;
этот архив предназначен для запуска через dev-сервер, не для production deployment.

## Проверка сценария
1. По умолчанию открыт работник Олександр. Найдите вакансию «Розробник інтерфейсів».
2. Нажмите «Відгукнутися», напишите письмо и отправьте.
3. Переключите демо-пользователя на компанию «Піксель Студія».
4. Откройте «Відгуки кандидатів», нажмите «Відповісти».
5. Выберите «Запрошення», напишите ответ и отправьте.
6. Вернитесь к Олександру → «Мої відгуки»: появятся ответ и статус.
Можно открыть две вкладки и выбрать разные аккаунты. Выбор хранится в sessionStorage
отдельно для вкладки, данные — в общей SQLite. Фоновое обновление каждые 3 секунды.
Демо-аккаунты: 3 компании и 2 работника. Для других вакансий выбирайте их компанию.

## Реализовано
- React-компоненты вместо ручной перерисовки innerHTML.
- Общая база SQLite: компании, работники, вакансии, отклики и ответы.
- Один отклик работника на вакансию (ограничение UNIQUE в базе).
- Компания получает только отклики на свои вакансии.
- История ответов, статусы sent/reviewing/invited/rejected.
- Создание и закрытие вакансии; закрытие не удаляет историю.
- Редактирование имени и навыков. В кабинете компании отображается актуальный профиль,
  не исторический снимок резюме на дату отклика.
- Поиск и фильтрация вакансий, ошибки API, блокировка кнопок при отправке.
- Статистика рассчитывается из реальных записей вместо фиктивных графиков.
- Сохранён базовый стиль и украинский язык исходного интерфейса.

## Структура
src/main.jsx — React UI, API-клиент и формы.
src/styles.css — исходные стили с дополнениями.
server.py — HTTP JSON API, проверки роли/принадлежности, SQLite.
vite.config.js — прокси /api на Python.

База jobly.sqlite3 создаётся рядом с server.py при первом запуске и сохраняется между
перезапусками. Для полного сброса остановите Python и удалите этот файл.
Исходный localStorage jobly-uk-v1 не переносится: там не было связей с аккаунтами.
Вкладки company.html и worker.html заменены единым React-приложением.
Раздел сохранённых вакансий не перенесён на этом этапе.

## Важно: границы безопасности и функциональности
Это локальное демо, а не готовая система авторизации. Заголовок X-Demo-User задаёт
аккаунт и может быть подделан. Проверки принадлежности есть, но без реального входа
они не защищают данные от пользователя, который меняет идентификатор.
Серверы слушают loopback: не открывайте их в интернет и не храните реальные резюме.
Нет регистрации, сессий, email/Telegram-уведомлений, загрузки файлов резюме,
двустороннего чата или инициативных приглашений от компаний без отклика.
Ответ доставляется внутри кабинета, не по почте. Старые сообщения сохраняются,
но нет отдельных флагов прочтения и непрочитанных уведомлений.

Перед публикацией: реальная аутентификация с безопасными сессиями, проверка
авторизации на сервере по сессии, CSRF-защита для cookie-сессий, HTTPS,
ограничение частоты запросов, production-сервер и резервное копирование.

SQLite: отправка, дубликат, права другой компании, ответ, получение ответа работником,
закрытие вакансии и сохранение истории. Это не браузерный end-to-end тест.
